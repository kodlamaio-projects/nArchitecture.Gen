## 💻 About The Project

As Kodlama.io, we have chosen to unveil examples of finalized projects. Natively integrated with Clean Architecture principles, nArchitecture CLI tool epitomizes cutting-edge development methodologies. This monolithic project incorporates Clean Architecture, CQRS, Advanced Repository patterns, Dynamic Querying capabilities, JWT and OTP authentication mechanisms, Google & Microsoft Auth integration, Role-Based Management systems, Distributed Caching powered by Redis, Logging functionalities leveraging Serilog, Elastic Search functionalities, and a feature-rich Code Generator. By actively contributing, you not only bolster the project but also acquire invaluable insights and expertise.

## ⚙️ Getting Started

To get a local copy up and running follow these simple steps.

### Prerequisites

- .NET 10 SDK

### Installation

1. Install the tool globally:
   ```sh
   dotnet tool install --global NArchitecture.Gen
   ```
   

   You can also install the tool locally in the project:
   1. Create dotnet tool manifest:
   ```sh
   dotnet new tool-manifest
   ```
   2. Install the tool locally:
   ```sh
   dotnet tool install NArchitecture.Gen
   ```
## 🚀 Usage

1. Run `nArchGen` command in project solution directory.

| Command | What it does |
|---|---|
| `nArchGen new <Name> [--security] [--starter-path <dir>]` | Creates a solution from the nArchitecture starter (`--starter-path` copies a local checkout instead of downloading the tagged release). |
| `nArchGen generate crud <Entity> <DbContext> [-c -l -t -s -d -m] [--force]` | CRUD feature: commands, queries, Mapperly mapper, repository, controller, operation claims. |
| `nArchGen generate command <Name> <Feature> [-e Post\|Put\|Delete]` / `generate query <Name> <Feature>` / `generate dynamic-query <Entity>` | Single command, query or dynamic query inside an existing feature. |
| `nArchGen upgrade [--dry-run] [--project <name>] [--keep-test-framework] [--skip <steps>] [--no-build] [--force]` | Upgrades a 1.x solution to 2.0, see below. |

`generate` commands never overwrite files: if any file they would create already exists, nothing is written and the
command lists the existing files. Pass `--force` to regenerate them; registrations, operation claim seeds and endpoints that
are already in place are not added a second time.

### Scripts, CI and AI agents

Every command runs without prompts when `--no-interactive` is passed, when its input is redirected or when the `CI`
environment variable is set. Pass the values as arguments; optional ones (mechanism flags, operation claim type) fall back
to their defaults, and a missing required one fails with the available choices instead of waiting for input. Errors go to
stderr and the exit code tells what happened:

| Exit code | Meaning |
|---|---|
| `0` | Success. |
| `1` | The command failed: a business rule was violated, or the upgraded solution does not build. |
| `2` | Invalid or missing arguments. |
| `3` | Files to be generated (or the project folder for `new`) already exist; nothing has been written. |
| `4` | Unexpected error, please [open an issue](https://github.com/kodlamaio-projects/nArchitecture.Gen/issues). |

### Upgrading a 1.x project

Run `nArchGen upgrade` in the solution folder of a project created with Gen 1.x. It moves the projects to `net10.0`, swaps
MediatR for `NArchitecture.Core.Mediator`, turns AutoMapper profiles into Mapperly mappers and rewrites the `IMapper` call sites,
updates `NArchitecture.Core.*` and friends to 2.0, migrates the test project to xunit.v3 + Microsoft Testing Platform, formats with
the solution's csharpier, builds, and writes `MIGRATION-REPORT.md` with everything it could not do by itself (notifications,
AutoMapper `ConstructUsing`/expression `MapFrom`, …). Start with `--dry-run` to see the report without touching files. The
companion guide with the manual steps lives in the Core repo:
[migration-guide-2.0.md](https://github.com/kodlamaio-projects/nArchitecture.Core/blob/main/docs/migration-guide-2.0.md)
([Türkçe](https://github.com/kodlamaio-projects/nArchitecture.Core/blob/main/docs/migration-guide-2.0.tr.md)).

### Building against unreleased Core packages

`NArchitecture.Gen` depends on `NArchitecture.Core.Mediator`. Until the matching Core version is on nuget.org, pack Core locally (`dotnet pack -c Release -o artifacts/packages` in the Core repo) and restore with an extra source:

```bash
dotnet restore --source https://api.nuget.org/v3/index.json --source ../nArchitecture.Core/artifacts/packages
```

## 🆕 What's new in 2.0

- Requires the **.NET 10 SDK**; generated code targets nArchitecture starter **2.0** and `NArchitecture.Core.*` **2.0.0**.
- Generated handlers use `NArchitecture.Core.Mediator` instead of MediatR (`using NArchitecture.Core.Mediator;`, same `IRequest`/`IRequestHandler` names).
- Generated mapping uses [Mapperly](https://mapperly.riok.app/) static mappers (`Features/<Entities>/Mappers/<Entity>Mapper.cs`) instead of AutoMapper profiles.
- `generate dynamic-query` now also adds the `GetListByDynamic` endpoint to the existing controller and generates its own Mapperly mapper.
- The tool itself runs on `NArchitecture.Core.Mediator` streaming requests; `MediatR` is no longer a dependency.
- New `nArchGen upgrade` command migrates 1.x solutions (Roslyn based rewrite of MediatR/AutoMapper code) and `nArchGen new --starter-path` creates projects from a local starter checkout.
